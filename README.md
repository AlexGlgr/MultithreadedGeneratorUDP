# MultithreadedGeneratorUDP
Проект создания генератора данных, для тестирования высокоскоростных сетевых интерфейсов 100...200 Gbit UDP трафиком.

## Описание
<div style = "color: #555">

Приложение server_cluster.js является приёмником UDP-трафика и является часть программного комплекса генератора данных для тестирования высокоскоростных сетевых интерфейсов. Приёмник при запуске использует ряд параметров, настраивающих режим его работы. Эти параметры могут быть либо считаны из конфигурационного файла, либо введены через ключи в командной строке при запуске. Приложение построенно на технологии кластеров - механизма для параллелизации процессов на Node.js. При запуске инициализируется главный кластер, который читает конфигурацию из указанного файла, выводит статистику, а также собирает информацию с дочерних кластеров, которые сам создаёт. Дочерние кластеры запускают слушают указанный порт и ведут подсчёт трафика. Также между передатчиком и приёмником системы устанавливается TCP-канал для обмена дополнительными и управляющими данными, например количество переданных пакетов по факту со стороны передатчика. Также предусмотрена работа в режиме справочника - приложение выводит только справочную информацию, полученную от передатчика по TCP-каналу, не создавая кластеры и сокеты для измерения трафика. 
</div>

## Параметры запуска
<div style = "color: #555">

Приёмник принимает следующие параметры запуска:
- <mark style="background-color: lightblue">portBase (-p)</mark> - начальный порт, с которого дочерние кластеры начинают измерять трафик (по-умолчанию = 50000);
- <mark style="background-color: lightblue">portCount (-o)</mark> - количество кластеров, слушающих каждый порт (по-умолчанию = 1);
- <mark style="background-color: lightblue">roundRobin (-r)</mark> - включение правила Round Robin распределения процессов (по-умолчанию = 0);
- <mark style="background-color: lightblue">baseCPU (-c)</mark> - начальный номер ядра, с которого начнётся распределения кластеров (по-умолчанию = 0);
- <mark style="background-color: lightblue">sockets (-s)</mark> - общее количество портов, трафик с которых необходимо измерить (по-умолчанию = 1);
- <mark style="background-color: lightblue">baseIP (-i)</mark> - начальный ip-адресс, с которого дочерние кластеры начинают измерять трафик (по-умолчанию = 0.0.0.0);
- <mark style="background-color: lightblue">stock (-q)</mark> - флаг, означающий, что все сокеты используют один и тот-же ip-адрес (по-умолчанию = 1);
- <mark style="background-color: lightblue">file (-f)</mark> - путь к конфигурационному файлу (по-умолчанию = './test.json');
- <mark style="background-color: lightblue">tcp (-t)</mark> - флаг, означающий, что приложение работает в режиме справочника и выводит только информацию по переданным пакетам с передатчика по tcp каналу (по-умолчанию = 0).


### Примеры
#### Использование server_cluster.js
<div style = "color: #555">

В ходе экспериментов на этапе тестирования выявлен оптимальный режим работы, когда создаётся множкство кластерой, каждый слушает по одному порту. Этот режим обеспечивает высокую удельную скорость в 37kpps на порт гарантировано без потерь. Поэтому значениями по-умолчанию такими и выбраны.

```js
// Для наглядности "посадим" на порты А0 и Р12 светодиоды 
let a_ports = H.DeviceManager.Service.CreateDevice('21');

// Явное задание режима порта
a_ports[0].Configure({ mode: 'af_output' });
a_ports[1].Configure({ mode: 'output' });

// Подадим аналоговый сигнал на А0
a_ports[0].SetValue(0.5, { freq: 50 });  
// Подадим цифровой сигнал на P12
a_ports[1].SetValue(1); 

```

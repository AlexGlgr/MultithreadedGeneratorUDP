# MultithreadedGeneratorUDP
Проект создания генератора данных, для тестирования высокоскоростных сетевых интерфейсов 100...200 Gbit UDP трафиком.

## Описание
<div style = "color: #555">

Приложение server_cluster.js является приёмником UDP-трафика и является часть программного комплекса генератора данных для тестирования высокоскоростных сетевых интерфейсов. Приёмник при запуске использует ряд параметров, настраивающих режим его работы. Эти параметры могут быть либо считаны из конфигурационного файла, либо введены через ключи в командной строке при запуске. Приложение построено на технологии кластеров - механизма для распараллеливания процессов на Node.js. При запуске инициализируется главный кластер и начинает слушать указанный в параметре ip-адрес и порт по протоколу TCP. По этому каналу от передатчика ожидаются управляющие команды для синхронизации и запуска процесса измерения трафика. Данные команды обеспечивают подъём встречного TCP-канала, настройка конфигурации, вывод статистики, окончание теста и приём статистики по переданным пакетам. Дочерние кластеры, созданные по полученной конфигурации, запускают слушают указанный порт и ведут подсчёт трафика и передают эти данные на главный кластер, выводящий общую статистику. 
</div>

## Параметры запуска
<div style = "color: #555">

Приёмник принимает следующие параметры запуска:
- <mark style="background-color: lightblue">port (-p)</mark> - порт, на котором создаётся управляющий TCP-канал;
- <mark style="background-color: lightblue">ip (-i)</mark> - адрес управляющего TCP-канала.

## Управляющие TCP пакеты
<div style = "color: #555">

По автоматически установленному при старте программы TCP-каналу приёмник ожидает от передатчика управляющие команды, содержащие конфигурации для функционирования приложения. Доступны следующие команды:
- <mark style="background-color: lightblue">register</mark> - получение данных для установки встречного tcp-соединения и дальнейшей синхронизации работы с передатчиком. Необходимо выполнить для корректного функционирования программы. Ожидаемая структура пакета:
```js
{
    com: 'register',        // тип команды
    ip: '10.120.100.52',    // ip-адрес на стороне передатчика, к которому устанавливается подключение с приёмника
    port: 7777              // порт на стороне передатчика
}
```
Ответ на успешное выполнение этой команды будет следующим:
```js
{
    com: 'registered', 
    name: 'cluster_server', 
    status: 'running'
}
```

- <mark style="background-color: lightblue">packets</mark> - инкрементирует глобальный счетчик полученных пакетов. Ожидаемая структура пакета:
```js
{
    com: 'packets',         // тип команды
    packets_send: 12181     // количество переданных пакетов, посчитаное передатчиком
}
```
Ответа на данную команду не предусмотрен.

- <mark style="background-color: lightblue">drypackets</mark> - инкрементирует глобальный счетчик полученных пакетов, а также выводит общую статистику в консоль. Необходим для работы приложения в режиме справочника, когда не создаются кластеры и не ведётся активный подсчёт трафика. Может быть выполнена сразу после запуска. Ожидаемая структура пакета:
```js
{
    com: 'drypackets',      // тип команды
    packets_send: 12181     // количество переданных пакетов, посчитаное передатчиком
}
```
Ответа на данную команду не предусмотрен.

- <mark style="background-color: lightblue">roundrobin</mark> - включает распределение нагрузок ядер по правилу Round Robin. По умолчанию этот параметр выключен, распределением нагрузки по ядрам занимается операционная система. Ожидаемая структура пакета:
```js
{
    com: 'roundrobin',      // тип команды
    rr: 1                   // 1 - флаг для включения RR, любое другое значение его выключит
}
```
Ответ на успешное выполнение этой команды будет следующим:
```js
{
    com: 'scheduled', 
    name: 'cluster_server', 
    status: 'running'
}
```

- <mark style="background-color: lightblue">start</mark> - запуск основного цикла работы датчика, вывод измеренного трафика по группам плюс общая. Запуск кластеров. Обнуление глобальных счетчиков. Ожидаемая структура пакета:
```js
{
    com: 'start',           // тип команды
    config: {}              // содержимое конфигурационного файла со всеми датчиками и их портами и адресами
}
```
Ответ на успешное выполнение этой команды будет следующим:
```js
{
    com: 'started', 
    name: 'cluster_server', 
    status: 'listenning'
}
```

- <mark style="background-color: lightblue">stop</mark> - остановка основного цикла работы датчика, вывод общего отчета о тесте. Закрытие всех дочерних кластеров. Ожидаемая структура пакета:
```js
{
    com: 'stop'             // тип команды
}
```
Ответ на успешное выполнение этой команды будет следующим:
```js
{
    com: 'stopped', 
    name: 'cluster_server', 
    status: 'running'
}
```


### Примеры
#### Использование server_cluster.js
<div style = "color: #555">

В ходе экспериментов на этапе тестирования выявлен оптимальный режим работы, когда создаётся множество кластеров, каждый слушает по одному порту. Этот режим обеспечивает высокую удельную скорость в 37kpps на порт гарантировано без потерь. Поэтому значениями по умолчанию такими и выбраны.
